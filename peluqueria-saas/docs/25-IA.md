# 25 — IA (opcional) (Etapa 21)

## 1. Qué problema resuelve

El roadmap marca esta etapa como opcional y doc `01-ANALISIS-Y-ARQUITECTURA.md`
§3 la define con una sola línea: `IA → Estadísticas, Clientes [flag: ai]`,
con la restricción explícita "nunca cruza tenants" (§2, Capa 5). Sin más
detalle en el pedido, se construyó lo mínimo coherente con esa definición:
un endpoint que le pide a un modelo de lenguaje un resumen accionable de
las estadísticas y clientes de UN negocio — nunca mezclado con los de
otro.

## 2. Dependencias

Depende de `ReportsService.getDashboard` (Etapa 20) y del feature flag
`ai` (ya sembrado desde el arranque del proyecto, sin ningún endpoint que
lo usara hasta esta etapa — mismo patrón que `whatsapp`/`facebook`/
`instagram` antes de sus etapas). Nuevo permiso `ia.ver`.

## 3. Credenciales: de la PLATAFORMA, no por-tenant

A diferencia de Mercado Pago para clientes / WhatsApp / Facebook /
Instagram (Etapas 15-17), donde cada negocio conecta SU PROPIA cuenta,
acá no hay "cuenta de IA" que un negocio pudiera tener — es una
capacidad que la plataforma ofrece sobre los datos del negocio. Las
credenciales (`AI_API_KEY`, API de Anthropic/Claude) son variables de
entorno de la plataforma, mismo criterio que `MERCADO_PAGO_ACCESS_TOKEN`
de la Etapa 5 (billing de la plataforma, no de cada negocio). Sin la
clave configurada, el endpoint responde 500 con un mensaje claro, mismo
patrón que `MercadoPagoService.credentials` (Etapa 5).

## 4. Endpoint

```
GET /ai/insights?from=&to=&branchId=   ia.ver + flag ai
```

`AiService.getInsights` arma el contexto llamando a
`ReportsService.getDashboard` (Etapa 20, ya tenant-scoped) más un conteo
de clientes activos/nuevos del mismo tenant, y se lo manda como JSON a la
API de Anthropic (`POST /v1/messages`, `src/ai/ai-client.ts` — función
pura parametrizada por credenciales, mismo molde que
`mercado-pago-client.ts`/`whatsapp-client.ts`/`meta-client.ts`) con un
system prompt que instruye "3 a 5 puntos accionables, sin mencionar otros
negocios". La respuesta devuelve tanto el texto generado (`insights`)
como los datos crudos usados (`basedOn`), para que el negocio pueda
verificar de dónde salió cada afirmación.

**"Nunca cruza tenants" en la práctica**: el JSON que se le manda al
modelo se arma exclusivamente con `TenantPrismaService`/`ReportsService`
(ya acotados al tenant del JWT) — nunca se agrega ni un campo de otro
negocio a esa misma consulta, y cada request es independiente (sin
memoria/contexto compartido entre negocios distintos).

## 5. Qué NO se hizo en esta etapa (a propósito)

- **Chat conversacional / asistente interactivo**: un solo endpoint que
  genera un resumen puntual, no una conversación de ida y vuelta — el
  pedido no detalla ese alcance y sería inventar UI/flujo no pedido
  (mismo criterio de restricción que WhatsApp/Instagram/Facebook,
  Etapas 16/17).
- **Recomendaciones automáticas que escriben datos** (ej. "ajustar
  precios automáticamente", "enviar promociones solo-IA"): el endpoint
  es de solo lectura — genera texto para que una persona lo lea y decida,
  nunca ejecuta acciones por su cuenta.
- **Caché/historial de insights generados**: cada llamada genera un
  resumen nuevo, no se persiste (no hay modelo nuevo en el schema para
  esto) — mismo criterio de "sin ledger" ya aplicado a WhatsApp/Instagram
  (Etapas 16/17) para mensajes entrantes.
- **Elegir entre múltiples proveedores de IA**: un solo proveedor
  (Anthropic), sin abstracción multi-proveedor — se puede agregar después
  si se pide, sin romper el endpoint actual (la función pura en
  `ai-client.ts` ya está aislada del resto por el mismo motivo que los
  otros `*-client.ts`).

## 6. Tests

`test/ai.spec.ts` (5 tests): sin el flag `ai` habilitado responde 403;
habilitado, devuelve el texto generado (mockeado) junto con los datos
(`basedOn`) usados para armarlo, usando las credenciales de la
plataforma; si la API de IA falla, responde 500 sin filtrar el detalle
técnico; sin `AI_API_KEY` configurada responde 500 con un mensaje claro y
nunca llega a llamar a `fetch`; aislamiento multi-tenant (los datos que
se le mandan al modelo son exclusivamente los del tenant que pide el
insight). 195 tests en la suite completa (5 nuevos).
